# Analytics findings — Search Console export of 2026-08-17

Source: three Search Console "Performance on Search" exports the site
owner uploaded to Drive — 2026-07-14, 2026-08-07 and 2026-08-17. The
last one covers the **last 3 months** (2026-06-26 → 2026-08-15, the full
range the property has data for) and is the basis for everything below.
The earlier two were merged to build the daily timeline.

The raw CSVs are in `analytics/inbox/`, one folder per export.

**Every number in this file is produced by
`scripts/analyse-gsc-exports.py`** — standard library, no network, no
credentials. Run it and compare. If the prose here disagrees with the
script, the script is right.

```bash
python3 scripts/analyse-gsc-exports.py
```

## The headline

**Half of every impression the site earns is a cloud-cost query. None
of them click.**

| Query theme | Impressions | Share | Clicks | Avg position |
|---|---|---|---|---|
| cloud cost / spend | 236 | **51.0%** | **0** | 76.1 |
| other | 54 | 11.7% | 0 | 57.3 |
| password managers | 52 | 11.2% | 0 | 55.4 |
| phones / iphone | 52 | 11.2% | 0 | 36.1 |
| network security | 28 | 6.0% | 0 | 67.3 |
| senior tech (general) | 18 | 3.9% | 0 | 140.0 |
| sysadmin / linux | 13 | 2.8% | 0 | 42.0 |
| ai troubleshooting | 10 | 2.2% | 0 | 70.7 |

Position 76.1 is page eight of Google. The site is visible for exactly
one topic and the searcher is seven pages away.

How the cloud bucket is counted, and why it needs two conditions: a
query only lands there if it mentions *cloud* (or Azure) **and** carries
spending intent. "cloud" alone catches cloud computing queries with no
budget behind them. The spending word alone catches the machine-generated
*"i'm 66+ and i spend around $124/month on technology"* queries, which
are about personal spending, not cloud. 236 impressions is the honest
middle ground, and it is the number the script prints.

The single page serving that cluster —
`/sysadmin/how-reduce-cloud-spend-before-year-end-2025/` — has **251
impressions, 0 clicks, average position 74.74**. It is the biggest page
on the site by impressions and it earns nothing.

The reason is in the title: *"How to Actually Reduce Your Cloud Spend
Before Year-End 2025"*. The post was published in December 2025 and
framed around a deadline that passed eleven months ago. The queries it
is being shown for still say "2025" because that is what the title
matches, and that is the whole problem.

**The fix landed after this data.** "Cloud for Cheap: What It Actually
Costs to Run Your Own" went live on 2026-11-10 and is the second entry
in this cluster. The cluster now has an anchor and a supporting post
instead of one expired one.

Two of these are title problems rather than ranking problems. The
iPhone setup post has a good title but its first line promises a
"30-Minute Setup" — a lot to read for a quick click. The
is-chatgpt-reading-your-parents-data post ranks at **16.19**, which is
page two, and loses all 79 impressions there.

The homepage at position 6.08 with 38 impressions and no clicks is
probably navigational — someone searched the brand, saw it, and did not
need to click. Worth checking, not worth panicking about.

The "???" query at position 2 is a real puzzle worth a look — Google
showed the site for a query nobody can write.

## How to keep seeing this

These exports are three months old. To refresh them, pull a fresh
"Performance on Search" export from Search Console (Last 3 months, and
the Dates tab for the daily timeline) and drop the CSV in
`analytics/inbox/` under a folder named after the export date — the same
layout as `gsc-export-2026-07-14` and `gsc-export-2026-08-17` here.
Commit it and the next analysis has a baseline to compare against.

No tooling required; the exports are CSV files and a spreadsheet reads
them fine.
